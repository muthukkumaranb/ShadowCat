# Stage Head Classification Report

> [!NOTE]
> **v1 vs v2 Performance Note (Post-Zero-Fill Retrain)**:
> Stripping the 12 fabricated packet-level features via Option A (zero-fill) resulted in a modest performance decline in the Stage Head classifier across the 37 LOEO folds.

### v1 vs v2 Performance Comparison
| Metric | v1 (Fabricated Features) | v2 (Option A Zero-Fill) | Delta (v2 - v1) |
|---|---|---|---|
| **LOEO Overall Accuracy** | **86.01%** | **83.68%** | **-2.33%** |
| **Credential Access Recall** | **0.573** | **0.488** | **-0.085** |

- **Root Cause Explanation**: This modest decline is consistent with the same root cause identified in the hazard head investigation — the stage head also consumes the full 406-feature input vector (including the 12 previously-fabricated packet columns), so a portion of its v1 performance was likely benefiting from the label-correlated fallback signal now correctly removed.

- **Input Verification**: Stage Head operates directly on **PREDICTED future latent state** $\hat{S}_{t+1}$ generated by LSTMGaussianWorldModel (v2 checkpoint: gaussian_next_state_best_v2.pt), fulfilling strict architectural requirements.
- **ATT&CK Mapping Source**: data/ucs/attack_tactics_mapping.yaml
- **Unknown/Other Fallback Rule**: All benign or unmapped/low-confidence traffic windows default to Unknown/Other.
- **Scope Verification**: Evaluated across all labeled windows (Claim Ladder Rung 4). B1 stage transition (n=1 infiltration) is strictly excluded (case study scope owned by ML2).
